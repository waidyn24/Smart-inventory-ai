# SMART INVENTORY AI — КАК ВЫЛОЖИТЬ В ИНТЕРНЕТ

Здесь готовый проект для облачной публикации: frontend (Next.js) и backend (FastAPI) работают через **ОДИН публичный адрес**. URL `/api/...` перенаправляется на внутренний API, поэтому в браузере больше нет адреса `localhost:8000` и нет кросс-доменных проблем с cookie/CSRF. База данных — либо встроенная SQLite с постоянным томом Railway, либо PostgreSQL на Render.

## СПОСОБ 1: RENDER (проще всего для бесплатного учебного демо)

1. Распакуйте ZIP. Откройте папку `smart-inventory-ai`. Файлы `Dockerfile` и `render.yaml` должны лежать в корне этой папки.
2. На https://github.com создайте **новый репозиторий**, например `smart-inventory-ai-online`.
3. Загрузите **содержимое папки** `smart-inventory-ai` (все файлы и папки, включая `Dockerfile` и `render.yaml`) в корень репозитория: **Add file -> Upload files -> Commit changes**. Не загружайте ZIP как один файл!
4. Откройте https://dashboard.render.com -> **New -> Blueprint**. Подключите GitHub, выберите репозиторий.
5. Render прочитает `render.yaml`, создаст **web service** + **PostgreSQL**, затем соберёт проект из `Dockerfile`. Дождитесь статуса **Live**.
6. Нажмите ссылку типа `https://smart-inventory-ai-online.onrender.com`. Должна открыться страница входа. Войдите `owner@demo.kz` / `Demo2026!`.
7. Проверка API: откройте `https://АДРЕС-САЙТА/api/health` — ожидается JSON с `"ok":true`.

**Ограничения Render Free:** сервис может «засыпать» и медленно открываться после перерыва. Бесплатная PostgreSQL база **истекает через 30 дней** (данные нужно забрать/перенести заранее); возможны дополнительные ограничения по ресурсам. Для постоянной работы нужна база/план без этой границы. Возможны изменения тарифов Render.

## СПОСОБ 2: RAILWAY (постоянная SQLite-база с Volume)

1. Загрузите содержимое `smart-inventory-ai` в корень репозитория GitHub, как выше.
2. Откройте https://railway.com/ -> **New Project -> Deploy from GitHub Repo** -> выберите репозиторий.
3. Railway найдёт корневой `Dockerfile` и соберёт один сервис (frontend и backend в одном контейнере).
4. В **Variables** сервиса добавьте `SESSION_SECRET`: длинную случайную строку (не меньше 48 символов). Установите `COOKIE_SECURE=true`, `ALLOW_DEMO_RESET=false`. **Не добавляйте** `DATABASE_URL`, если используете встроенную SQLite.
5. Для сохранения товаров и продаж после обновлений: откройте сервис -> **Settings -> Volumes -> Add Volume**, задайте mount path **`/data`**. **Это обязательно, чтобы данные SQLite не терялись при redeploy**.
6. В **Settings -> Networking -> Generate Domain** получите ссылку `https://...up.railway.app`.
7. Откройте ссылку и войдите `owner@demo.kz` / `Demo2026!`. Проверка API: `https://ДОМЕН/api/health`.

Railway может потребовать пополнения счёта/платного тарифа; условия уточните в своём аккаунте. Не подключайте несколько экземпляров сервиса к одной SQLite базе.

## ВАЖНО

- Просто перетаскивать ZIP в **Netlify Drop** нельзя: он не разворачивает FastAPI и PostgreSQL.
- Этот ZIP **не создаёт интернет-ссылку сам по себе**. Чтобы сайт заработал в интернете, необходимо выполнить шаги на Render или Railway и дождаться успешного развёртывания.
- Демо-аккаунты и пароль в интерфейсе являются **общедоступными**. Не используйте настоящие данные покупателей и магазина. Сброс демо-данных через API в онлайн-конфигурации выключен.
- Время первого запуска зависит от хостинга. При ошибках смотрите **Deploy Logs** сервиса.
- Для настоящего магазина нужны индивидуальные аккаунты, резервное копирование, ограничения по доступу и защита от посторонних изменений.
- Если хотите использовать локальную Docker-версию, инструкция в исходном `README.md`. Локальный compose оставлен для совместимости.

## КАК УСТРОЕН ОБЛАЧНЫЙ РЕЖИМ

```text
Интернет (HTTPS)
      │
      ▼
 Next.js, $PORT — страницы, CSS, изображения
      │
      └── /api/* -> 127.0.0.1:8000/* (внутренний FastAPI)
                                     │
                                     ▼
                         PostgreSQL / SQLite (/data)
```

В браузере всё открывается по одному HTTPS-домену, поэтому cookies и CSRF работают без дополнительных доменов/CORS.
